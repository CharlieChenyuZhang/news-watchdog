## TLDR

- **PHP2Shell: frontier AI found and weaponized decade-old bugs in core PHP; patches shipped today (NEW; Confirmed).** Two CVEs (**CVE-2026-109618 / -109619**, CVSS up to 9.2) cover four use-after-free / type-confusion bugs in how PHP handles fatal out-of-memory errors across requests. Wiz demonstrated **pre-auth RCE on WordPress, Drupal and Joomla** and application-agnostic **memory disclosure** (tokens, API keys) even on a "Hello World" app; "every PHP version released in the last decade," back to 5.4, is affected by at least one bug. Fixed releases: **PHP 8.5.12, 8.4.27, 8.3.36, 8.2.35**. Wiz used Wiz Atlas, **Gemini 4 Argon** and **GPT-5.6 Sol**; Calif independently found a flaw with GPT-5.6 Sol under OpenAI's **Patch the Planet**, which coordinated maintainers, CDNs/WAFs (Cloudflare, AWS, Google, Microsoft, Fastly, Akamai, Vercel…) and US agencies (ONCD, CISA). OpenAI also committed **$1B in subsidized Daybreak access** for under-resourced defenders and calls this "one of the most impactful security issues in recent memory." HN: pre-announcement **1,358/569c**, release 172, PHP2Shell 39 (climbing); Dutch NCSC site offline (HN 188) and BBC reports European sites taken down ahead of the patch. **Founder action today:** patch every PHP host (incl. WordPress marketing sites and vendor-hosted PHP), confirm your WAF/CDN rule is on, and watch for multipart requests followed by memory-limit errors. [Wiz](https://www.wiz.io/blog/php2shell-php-rce) · [OpenAI](https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/) · [Cloudflare WAF](https://blog.cloudflare.com/php-vulnerabilities-waf-protection/) · [HN](https://news.ycombinator.com/item?id=50172041) · [Verge](https://www.theverge.com/tech/1015257/php-vulnerability-patch-website-security-wordpress)

- **LiteLLM 1.107.0 on PyPI shipped a credential stealer in all 7 wheels (NEW; Confirmed, cause not yet known).** Uploaded **4:39 AM PT today**; AISLE flagged it in 3m14s and PyPI quarantined it. The wheels drop `cook.pth`, `cook.py` and `sitecustomize.py` into `site-packages`, so it runs on **every Python start** even if you never import litellm: it steals browser passwords, SSH/GPG keys, cloud and k8s creds, CI secrets, AI tool config and all env vars, exfiltrates to lookalike `litellm.dev`, and installs an hourly remote-code loader (dormant when checked). Source tag and sdist are clean, which points to a compromised build/publish step or token. This is LiteLLM's **second** PyPI compromise this year (April incident). **If any machine or CI image installed 1.107.0: treat it as compromised, delete those files, rotate every credential, pin 1.106.2.** [AISLE](https://aisle.com/blog/litellm-11070-on-pypi-shipped-a-credential-stealer) · [GitHub release](https://github.com/BerriAI/litellm/releases/tag/v1.107.0) · [Wiz](https://www.wiz.io/blog)

Browsers are fine (CT enforced), but **curl, Python, Node, Go, Java and CI runners trusted forged certs in his tests**. Update `ca-certificates`/certifi/Node and rebuild base images. HN **1,103 + 447**.
